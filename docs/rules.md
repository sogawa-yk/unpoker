# unpoker 基本ルール

> ブラウザゲーム実装の基準となるルール定義。
> 本文（1〜14章）はオリジナルのルールをそのまま整理したもの。実装時に解釈が必要だった点の決定は末尾の「付録 B. 確定仕様」にまとめている（本文より優先）。

---

## 設計方針（2026-11-07）

- **基本は運試し。** 実力差が出にくいことを、このゲームの面白さとして残す。
- **ちょっとだけ実力が出る。** ただしその判断は難しいので、お金を払って AI に相談できる。
- **AI に聞いても、勝てるかは運次第。** AI が上げるのは勝率であって、勝ちを保証するものではない。
- **情報や助言を買ったお金は、次のゲームの持ち越しポットに入る。** 今のゲームで得た有利を、次のゲームでみんなに還元する。
- **山場は 2 つ。** 交代で札をめくる「公開フェーズ」が 1 つ目、チャレンジが 2 つ目。

---

## 1. 使用カード

- トランプ 52 枚を使用する
- ジョーカーは使用しない

## 2. 参加人数

- 3 人 または 4 人

## 3. ゲームの準備

1. 山札をシャッフルする
2. 各参加者に 7 枚ずつカードを配る
3. 配布終了後、場（コミュニティカード）に以下の枚数を表向きで置く

| 人数 | 初期の場札 |
|---|---|
| 3 人プレイ | 2 枚 |
| 4 人プレイ | 1 枚 |

## 4. 各参加者のカード配置フェーズ

各参加者は、配られた 7 枚のカードを以下の手順で扱う。

1. 7 枚のうち **任意の 3 枚** を自分だけ確認する
2. 確認した 3 枚の中から **1 枚を裏向きのまま場に置く**
   - このカードは場のカードに追加される
3. 残りのカード構成
   - 表を確認した 2 枚
   - 未確認の 4 枚
4. 上記 6 枚を使い、以下を作成する
   - **2 枚 1 組 × 3 セット**
   - すべて裏向き
   - 自由な組み合わせで作成する

## 5. 場のカード公開

- 全参加者が 3 セットを作り終えた後、各参加者が場に置いた裏向きカードをすべて表向きにする
- これにより、場のカードは合計 **5 枚** となる
  - 3 人プレイ：初期 2 枚 ＋ 各自 1 枚 × 3 ＝ 5 枚
  - 4 人プレイ：初期 1 枚 ＋ 各自 1 枚 × 4 ＝ 5 枚

## 6. 役の作成と評価方法

1. 各参加者は、自身の 3 セットそれぞれについて役を判定する
2. 役の作成方法（テキサスホールデム方式）
   - 場のカード 5 枚 ＋ 対象セットの 2 枚（計 7 枚）
   - その中から最も強い 5 枚の役を作成する
3. 役の強さは、一般的なポーカー（テキサスホールデム）の役順位に従う

## 7. 仮順位の決定（チャレンジ前）

- 各参加者の「3 セットの中で最も強い役」を抽出する
- その役同士を比較し、**仮順位（1 位〜最下位）** を決定する

**同役の場合**

- キッカーを含めたカードランクで比較する
- 完全に同一の場合は同順位とする

## 8. チャレンジ（救済）フェーズ

### 8-1. チャレンジ権の発生

- 仮順位が **最下位** の参加者は、100 点を追加で支払うことで、**仮 1 位** の参加者に対してチャレンジを行うことができる

### 8-2. 他参加者の参加

- 仮 2 位、仮 3 位（4 人プレイ時）の参加者も、各自 100 点を追加で支払うことでチャレンジに参加できる
- チャレンジ参加者は複数可

### 8-3. 場のカード変更

- チャレンジが発生した場合、場のカード 5 枚のうち 1 枚をランダムで選択する
- 選ばれたカードを除外し、山札からランダムで 1 枚引き、場に表向きで追加する
- 変更後、場のカードは再び 5 枚となる
- 除外されたカードは以降使用しない

## 9. チャレンジ後の役再評価

1. 場のカード変更後、すべての参加者は自身の 3 セットの役を再評価する
2. その結果、最も強い役を持つ参加者が **最終勝者** となる

## 10. 得点処理

### 10-1. 基本ベット

- ゲーム開始時に、各参加者は 100 点をベットする

### 10-2. チャレンジ時の点数

- チャレンジ参加者は、参加時に追加で 100 点を支払う
- この点数は **チャレンジポット** として扱う

### 10-3. 勝者の獲得点数

最終勝者は、以下をすべて獲得する。

1. 最初のベット点数（全員分）
2. チャレンジポットの全額

## 11. ナッツボーナス（チャレンジ後適用）

### 11-1. ナッツの定義

以下のいずれかを満たす役をナッツとする。

- ロイヤルストレートフラッシュ
- または、場のカード状況において理論上最強の役

### 11-2. ナッツ時の得点

- チャレンジ後の最終役がナッツであった場合、**最初のベット点数のみを倍** として獲得する
- チャレンジにより追加された点数は倍にならない

## 12. 勝敗確定

- 上記すべての処理終了後、点数の支払い・獲得を行い、1 ゲーム終了とする

## 13. 実装向け補足

- チャレンジの有無は、仮順位確定後に選択制とする
- チャレンジ参加受付は 1 回のみ
- UI 上は以下を明確に分けると理解しやすい
  - 「仮順位表示」
  - 「チャレンジ参加ボタン」
  - 「場カード再抽選演出」

## 14. このルールの特徴

- 負け確定局面からの逆転が可能
- 運要素を残しつつ、「100 点を払う価値があるか」という戦略的判断が生まれる
- 観戦・配信向けのドラマ性が高い

## 付録 A. ゲーム進行フロー（参考）

```
準備（シャッフル → 7枚配布 → 初期場札）
  → 配置フェーズ（3枚確認 → 1枚を場へ → 3セット作成）
  → 場札公開（5枚）
  → 公開フェーズ（交代で自分の札を1枚ずつ選んでめくる）【山場1】
  → 役判定 → 仮順位表示
  → 最下位がチャレンジを宣言するか（1回のみ）
       ├─ しない → 仮順位で確定
       └─ する → 仮1位が強制参加（参加費を払う）
               → 2位・3位が参加するかを選ぶ（同時）
               → 場札1枚入れ替え演出 → 参加者＋仮1位で役再評価【山場2】
  → 得点処理（ナッツボーナス判定含む）
  → ゲーム終了
```

## 付録 B. 確定仕様（2026-11-07 決定）

原文から一意に決まらなかった点の決定事項。**本文と食い違う場合はこの付録を優先する。**
「既定」と付けた項目はユーザー確認前に置いた初期値で、変更可。

**読み替え**：本文に出てくる「100 点」（基本ベット、チャレンジ参加費）は、すべて **そのゲームのベット額 B** に読み替える（B-0 参照）。

### B-0. ルーム設定（ルーム作成時に決める）

| 設定 | 選択肢 | 初期値 |
|---|---|---|
| 初期持ち点 | 500〜10000（100 刻み） | 1000 |
| ベット方式 | **固定** ／ **持ち回り** | 固定 |
| 固定ベット額 | 10〜1000（10 刻み） | 100 |
| 持ち回り：最低ベット | 10〜1000（10 刻み） | 100 |
| 持ち回り：最高ベット | 最低ベット以上、または上限なし | 500 |
| 持ち回り：刻み幅 | 10 ／ 50 ／ 100 | 50 |
| 規定ゲーム数 | 5〜50、または無制限 | 10 |

（範囲と初期値は［既定］）

**ベット額 B の連動**

- そのゲームのベット額を **B** とする
- 基本ベット ＝ B
- チャレンジ参加費 ＝ B
- ナッツの増額分 ＝ 敗者 1 人あたり B（上限は B-4 のとおり）

**持ち回り方式**

- ゲームごとに「親」が交代し、親がそのゲームの B を決める。交代は席順で、脱落者は飛ばす。最初の親はランダム
- 親は配布の前に、手元のスマホで B を選ぶ。選べる範囲は、最低ベット〜min(最高ベット, 親の持ち点)
- 持ち点が B に足りない参加者がいても、親は B を選べる（その参加者はオールイン。B-3 参照）
- 親が 30 秒以内に選ばなければ、最低ベットになる［既定］
- 選べる額は、最低ベットから刻み幅ごとに、min(最高ベット, 親の持ち点) まで。親の持ち点が最低ベットより少なければ、最低ベットだけ（親もオールイン）［既定］
- 親の選ぶ持ち時間も、テーブルの一時停止で止められる。ベット額が決まると、iPad に大きく発表する［既定］
- 決まった B は iPad に大きく表示する

### B-1. 対戦形態・持ち点

| 項目 | 仕様 |
|---|---|
| 対戦形態 | **オンライン対戦**（複数端末・ルーム制。3〜4 人） |
| 初期持ち点 | ルーム設定（初期値 1000 点。B-0） |
| 進行 | **連続プレイ**。ゲームを繰り返す |
| 脱落 | ゲーム開始時の持ち点が **0** の参加者は脱落（B 未満でもオールインで参加できる） |
| 終了条件 | 残り 1 人、または規定ゲーム数の消化（B-0）。規定数で終わった場合は、持ち点が最も多い人が優勝 |

> 残り 2 人になったら、そこで対局を終了し、持ち点で順位を確定する［既定］。

#### 端末構成（旅行先で対面プレイする想定）

ローカルネットワークではなくオンライン方式を採る。理由は次のとおり。

- ホテル等の Wi-Fi では、端末同士の通信が遮断されていること（クライアント分離）がある
- iPad や iPhone のブラウザは自分でサーバーを立てられない
- 各自のモバイル回線（4G/5G）だけで遊べる

| 端末 | 役割 | 表示・操作 |
|---|---|---|
| iPad | **テーブル** | `/table/<ルームID>` を開く。場札、仮順位、チャレンジ参加者、場札の入れ替え演出、持ち点、参加用の QR コード。公開情報だけを受け取る |
| iPhone 等のスマホ | **手札**（1 人 1 台） | QR コードから参加する。7 枚から 3 枚めくる、1 枚を場に出す、2 枚ずつ 3 セット組む、チャレンジに参加するかを選ぶ。自分の札だけを受け取る |
| ゲームサーバー | 進行役 | ゲームの状態と山札をすべて持つ。各端末の操作が正しいかを確かめ、見てよい情報だけを WebSocket で送る |

ルール 13 章の「仮順位表示」「チャレンジ参加ボタン」「場カード再抽選演出」は、表示と演出をテーブル（iPad）、ボタンを手札（スマホ）に分けて担当させる。

#### 非機能要件

| 項目 | 要件 |
|---|---|
| 状態管理 | ゲームの状態はすべてサーバーが持つ。各端末は表示するだけで、山札や相手の札を端末に送らない（不正防止） |
| 再接続 | iOS Safari は画面ロックやアプリ切り替えで接続が切れる。自動で再接続し、現在の状態をサーバーから受け取り直す。誰の端末かは、ルームごとに発行したトークンを端末に保存して見分ける |
| 切断中の進行 | 各手番に持ち時間を設け、過ぎたら自動で操作する［既定］。配置フェーズ（60 秒）は smart 戦略で自動配置、公開フェーズ（10 秒）はランダムにめくる、チャレンジの宣言・便乗（20 秒）は見送り、親のベット額選び（30 秒）は最低ベット |
| 持ち時間の一時停止 | テーブル（iPad）から持ち時間を止め、再開できる。止めている間も操作はでき、演出は進む。再開すると止めたときの残り時間から続く |
| スリープ防止 | テーブル画面では Screen Wake Lock API を使う（iOS Safari で安定して動くかは未検証）。iPad の設定で「自動ロック：なし」にすることを推奨 |
| 通信 | HTTPS / WSS 必須（QR コードからの参加と Wake Lock API の前提）。通信量はごくわずかで、モバイル回線で足りる |
| ホスティング | OCI 大阪リージョン（Container Instances ＋ Flexible LB ＋ NoSQL）。Cloudflare 経由で公開する。詳細は docs/architecture.md |

### B-2. チャレンジ

| 項目 | 仕様 |
|---|---|
| 発生条件 | **仮最下位だけ**がチャレンジを宣言でき、宣言したときだけ発生する（2026-11-07 改定。シミュレーションの「新案 A」） |
| 受付の順序 | ① 仮最下位が宣言するか選ぶ → ② 宣言した場合、仮 2 位・仮 3 位が参加するかを同時に選ぶ。受付は各段階 1 回のみ |
| 仮 1 位 | **強制参加**。チャレンジが発生したら、**参加費 B を払う** |
| 仮 2 位・仮 3 位 | 任意参加。最下位が宣言したときだけ参加できる |
| 仮 1 位が複数 | 同率の全員を仮 1 位として扱う。全員が強制参加し、それぞれ参加費を払う |
| 仮最下位が複数 | 同率の全員が同時に宣言するか選ぶ。1 人でも宣言すれば発生し、宣言しなかった同率最下位は ② の任意参加に回る |
| 参加費 | B。残りの持ち点が B に足りなければ、残り全額（オールイン）で参加する。任意参加者は、残りが 0 なら参加できない。仮 1 位は、残りが 0 でも勝者候補のまま（払える分だけ払う） |
| 不参加者の扱い | **勝者候補から外れる**。基本ベットは失う |

**チャレンジ後の勝者判定**

- 勝者候補 ＝ 仮最下位（宣言者） ＋ 任意参加者 ＋ 仮 1 位（同率なら全員）
- 場札入れ替え後、勝者候補の中で最も強い役を持つ参加者が最終勝者
- 非参加者は再評価後の役が最強でも勝者にならない
- チャレンジが発生しなかった場合は、仮順位どおりに確定する

### B-3. 得点分配

| 項目 | 仕様 |
|---|---|
| 獲得 | 最終勝者が基本ベット（全員分）＋チャレンジポット全額を獲得（全員が B を払えた場合） |
| 同点の勝者 | **等分**。割り切れない端数は**席順が早い勝者**に渡す |
| オールインがある場合 | 下の「サイドポット」で分ける |
| 持ち越しポット | 前のゲームでの追加めくり（B-5）と AI 相談（B-6）の料金。このゲームの最終勝者が、基本ベットと一緒に受け取る（同点なら等分）。ナッツボーナスの 2 倍の対象外［既定］ |
| 持ち越しポットの払い戻し | 残り 2 人以下になって対局が途中で終わり、受け取る次のゲームがない場合は、払った人へそれぞれ払った額を返す［既定］ |

**オールイン**

- 持ち点が B に足りない参加者は、持ち点の全額を基本ベットとして出し、オールインになる
- オールインの参加者は、自分が出した額までしか、各相手から受け取れない（ポーカーと同じ考え方）

**サイドポットの計算**

1. 各参加者の拠出額 ＝ 基本ベット ＋ チャレンジ参加費（払った分だけ）
2. 拠出額を小さい順に並べ、その段ごとにポットを分ける
   - 各段のポット ＝ 全参加者から、その段の幅の分だけ集めた額
   - その段の受け取り資格 ＝ 勝者候補（B-2）のうち、拠出額がその段以上の人
3. 各段のポットは、資格がある人の中で最も強い役の人が取る（同点なら等分）
4. 資格がある人が 1 人もいない段は、その段に出した人へそのまま返す

**例（3 人・B＝300・チャレンジなし）**

- A の持ち点は 120 なのでオールインで 120、B と C は 300 を出す
- 1 段目（0〜120）：120 × 3 ＝ 360 → 資格は A・B・C
- 2 段目（120〜300）：180 × 2 ＝ 360 → 資格は B・C
- A が最強なら、A は 360 を取り、2 段目の 360 は B と C のうち強いほうが取る

### B-4. ナッツボーナス

| 項目 | 仕様 |
|---|---|
| 適用タイミング | **最終確定時に判定**。チャレンジの有無に関係なく適用する |
| ナッツ判定 | 最終の場札 5 枚に対し、使われていない札も含めて可能なすべての 2 枚の組み合わせを考えたときの最強役と同じ強さ（キッカーまで同じ）であればナッツ。ロイヤルストレートフラッシュは常にナッツ［既定］ |
| 増額分 | **敗者が追加負担**。敗者 1 人あたり、min(勝者が出した基本ベット, 敗者の残りの持ち点) を勝者に支払う。全員が B を払えた場合は B |
| 支払い不足 | 敗者の持ち点が足りない場合は、残りの持ち点を全額支払う |
| チャレンジポット | 2 倍の対象外（原文どおり） |
| 同点の勝者 | 同点の勝者は同じ強さなので、全員がナッツ。増額分は、勝者のうち出した基本ベットが最も多い人を上限として集め、B-3 のサイドポットと同じ考え方で分ける |

**計算例（4 人・B＝100・最下位が宣言し 2 位が参加・勝者の役がナッツ）**

- 基本ベット 100 × 4 ＝ 400
- ナッツ増額：敗者 3 人 × 100 ＝ 300
- チャレンジポット 100 × 3 ＝ 300（最下位・2 位・強制参加の 1 位）
- 勝者の獲得 ＝ 1000（勝者自身が出した 200 を含む）

> 「基本ベット分を 2 倍」は、勝者自身の 100 は倍にせず、増額は敗者からの徴収分（敗者 1 人あたり 100）だけとする（2026-11-07 確認済み）。

### B-5. カード処理

| 項目 | 仕様 |
|---|---|
| 「任意の 3 枚」の確認 | 裏向きに並んだ 7 枚から位置を 3 つ選んでめくる。中身はランダム［既定］ |
| 追加でめくる（有料） | **3 枚を超えてめくれる。1 枚ごとに 0.25B を払い、そのお金は次のゲームの持ち越しポットに入る**（2026-11-07 採用。シミュレーションでの案 B）。最大で 7 枚全部めくれる。何枚めくったかは iPad に公開し、中身は公開しない。0.25B は、AI と組み合わせたときにちょうど損得なしになる値段（docs/simulation.md「料金の試算」） |
| 追加でめくる：細目 | 料金は 0.25B の端数を切り上げる（B＝10 なら 3）。めくれるのは場に札を出す前まで。持ち点（基本ベットを払った残り）が料金に足りなければめくれない。規定ゲーム数の最終ゲームでは、受け取る次のゲームがないのでめくれない［既定］ |
| 場に出す札 | めくった札（3 枚以上）の中から 1 枚を選ぶ |
| セット作成 | 確認した 2 枚・未確認の 4 枚を自由に 2 枚ずつ組む。未確認の札は組んだ後も見られない（公開は B-7 の公開フェーズ）［既定］ |
| 入れ替え用の山札 | 配布と初期場札の残り（3 人：29 枚、4 人：23 枚）から 1 枚引く［既定］ |
| 除外カード | 以降使用しない（原文どおり） |

### B-6. AI 相談

チャレンジの判断などで、お金を払って AI に最善手を相談できる機能。払ったお金は**次のゲームの持ち越しポット**に入る。今のゲームでの有利を、次のゲームでみんなに還元する形になる。

| 項目 | 仕様 |
|---|---|
| 相談したことの公開 | **公開する**（2026-11-07 決定）。iPad の該当する席に「AI 相談中」と出す。その判断が済んだ後も「AI 相談 N」（そのゲームでの回数）を残す |
| 持ち越しポットの受け取り | 相談した本人も、次のゲームで勝てば受け取れる（2026-11-07 決定） |
| 持ち越しポットの分配 | 次のゲームの最終勝者が、基本ベットと一緒に受け取る。ナッツボーナスの 2 倍の対象外［既定］ |
| アドバイスの形 | 命令ではなく数字で見せる（例：「勝率 27%、乗れば期待値 +0.4B、3 位も乗れば −0.1B」）［既定］ |
| AI の知識 | **相談した本人が見えている情報だけ**を使う（2026-11-07 決定）。配置フェーズでは推定になる。チャレンジの時点では全員の札が公開済みなので、本人の情報だけでも正確な勝率が出る |
| 相談できる場面 | 配置フェーズ（追加でめくるか、どの札を場に出すか、どう組むか）とチャレンジの判断（宣言、便乗）［既定］ |
| 相談料 | **チャレンジの判断（宣言、便乗）：0.25B ／ 配置フェーズ：0.1B**。どちらも、相談で上がる期待値とほぼ釣り合う値段（docs/simulation.md「料金の試算」）。1 回の相談で 1 つの判断について答える |
| 最終ゲームでの相談 | **相談できない**。受け取る次のゲームがないため。追加めくり（B-5）と同じ扱い［既定］ |
| 料金の細目 | 端数は切り上げる（B＝10 なら配置 1、チャレンジ 3）。同じ判断は 1 回だけ払う（答えは何度でも見直せる）。配置は「場に出す札」と「組み方」が別の判断で、追加でめくった後は「場に出す札」をもう一度相談できる。チャレンジの判断は、払った後に参加費を出せる持ち点が残るときだけ相談できる［既定］ |
| 配置の答え | 場に出す札の候補ごとの「仮順位で 1 位になる見込み」、おすすめの組み方、1 枚追加でめくった場合の見込み。見えていない札をランダムに配ったモンテカルロで、相手は札を適当に組むと仮定した推定。組み方のおすすめは、組み方の画面の空いた枠に薄く出す（置くのは本人）［既定］ |
| チャレンジの答え | 挑む（乗る）・見送るそれぞれの勝率と期待収支（点）。入れ替えの全パターン（場札の位置 × 見えていない札）を数え上げる。他の人の判断は、他の人も期待収支で決めると仮定して予想し、判断ごとの内訳も見せる［既定］ |

### B-7. 公開フェーズ（山場 1）

場札 5 枚を公開した後、仮順位を出す前に、各自の 3 セット（6 枚）を交代でめくっていく。

| 項目 | 仕様 |
|---|---|
| めくる札 | 自分の番に、**自分の伏せ札から 1 枚を自分で選んで**めくる（2026-11-07 決定）。中身を知っている札も、知らない札も選べる |
| 順番 | 親から席順に 1 枚ずつ。固定ベット方式でも、親はゲームごとに交代する［既定］ |
| 1 回の持ち時間 | 10 秒。過ぎたら、残りの札からランダムにめくる［既定］ |
| 途中経過 | めくるたびに、各席の「今見えている札でできる一番強い役」を iPad に表示する |
| 終わり | 全員の 6 枚がめくれたら役判定をし、仮順位を出す |

- 自分でも中身を知らない札を、いつめくるかが演出上の選択になる。勝敗には影響しない。
- この後のチャレンジの時点では、全員の札が公開済みになる。山札の残りの中身も逆算できるので、AI は正確な勝率を出せる。
